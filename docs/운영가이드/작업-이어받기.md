## 1. 지금 어디까지 왔나

```
기획(GATE 1) ✅ → 설계(GATE 2) ✅ → 구현 ✅ → 마이그레이션(GATE 3) ✅ → 코드 리뷰 8건 수정 ✅ → 설계 v1.9 구현 ✅
  → QA GATE 4 1차 불통과(High 2) → 수정 → 재판정 통과 ✅ (2026-09-05) → 문서 ✅ (릴리즈 노트 v0.2.0)
```

제품의 핵심 루프 — **주간 식단 자동 생성 → 자동 주문 → 배송 시점 냉장고 자동 등록 → 조리·자동 차감 → 잔여분만큼 다음 주문 감산** — 이 코드 상으로 닫혔고, QA 가 가상 시계로 **1사용자 4사이클(9/13·9/20·9/27·10/4)** 을 실제 DB 에서 돌려 이음매마다 데이터가 흐르는 것을 확인했다(시나리오 191건 중 186 PASS, FAIL 5건은 전부 Low).

**남은 것은 main 머지(PR)와 후속 Low 5건·실키 확보 후 재검증이다.** 자세한 목록은 8장.

## 3. 로컬 환경 세우기

상세는 [install-guide.md](./install-guide.md) / [config-guide.md](./config-guide.md) / [backend-portable-guide.md](./backend-portable-guide.md).

```bash
cp .env.example .env
# JWT_SECRET 채우기: openssl rand -hex 32
docker compose up -d --build      # db + backend, 마이그레이션(0012 까지) 자동 적용, 스케줄러 2개 기동

cd frontend && npm install
echo "BACKEND_URL=http://localhost:8000" > .env.local
npm run dev
```

**포트 주의**: 원래 개발 머신에서는 5432/8000 을 다른 프로젝트가 점유해 `.env` 에
`POSTGRES_PORT=5433` / `BACKEND_PORT=8001` 을 썼다. 새 머신에서 포트가 비어 있으면
`.env.example` 기본값(5432/8000)을 그대로 쓰면 된다. 바꿀 경우 `DATABASE_URL` 과
`TEST_DATABASE_URL` 의 포트, `frontend/.env.local` 의 `BACKEND_URL` 도 같이 맞춘다.

## 7. 배포 상황 — 백엔드는 로컬에서 돌린다

요금 문제로 상시 백엔드 서버(`api.jaringobe.cloud`)를 내렸다. **백엔드는 로컬 docker 로 돌리는 것이 현재 정본이다.**

### 개발은 전부 로컬로 완결된다 — 터널이 필요 없다

3장대로 하면 백엔드·DB·프론트가 전부 로컬에서 돌고 외부 의존이 없다.

```
브라우저 → localhost:3000 (Next.js) → rewrites 프록시 → localhost:8000 (FastAPI) → localhost:5432 (postgres)
```

검증된 동작: 게스트 홈 200 / API 프록시 401(정상) / 소셜 로그인 authorize 302 / 스케줄러 실루프(5초 주기) 단계 전이.
**개발·테스트만 할 거라면 이 장의 나머지는 읽지 않아도 된다.**

### 터널은 "Vercel 프론트를 쓸 때만" 필요하다

`https://jaringobe.cloud` (Vercel) 는 인터넷에 있고 로컬 백엔드는 `localhost` 라 서로 닿지 않는다.
현재 Vercel 프론트는 정적 화면(`/ko`)은 200 이지만 **API 는 전부 502** 다 — `BACKEND_URL` 이
사라진 백엔드를 가리키기 때문이다. 이걸 살리려는 경우에만 터널이 등장한다.

| 상황 | 터널 |
|------|------|
| 내 PC 에서 개발·테스트 | **불필요** |
| 팀원/외부에 시연 | 필요 |
| Vercel 프론트를 살려야 함 | 필요 |

1. **임시 (quick tunnel)** — 계정 불필요, 1분.
   ```bash
   cloudflared tunnel --url http://localhost:8000
   ```
   출력된 `https://xxxx.trycloudflare.com` 을 Vercel `BACKEND_URL` 에 넣고 재배포.
   **프로세스가 죽으면 URL 이 바뀌어 Vercel 을 매번 다시 고쳐야 한다** (실제로 두 번 죽었다).

2. **고정 (named tunnel)** — `api.jaringobe.cloud` 고정 주소. 도메인을 이미 보유하고 있어 추가 비용 없음.
   첫 단계가 브라우저 로그인이라 사람이 직접 해야 한다.
   ```bash
   cloudflared tunnel login
   cloudflared tunnel create jaringobe-api
   cloudflared tunnel route dns jaringobe-api api.jaringobe.cloud
   cloudflared tunnel run --url http://localhost:8000 jaringobe-api
   ```
   이후 Vercel `BACKEND_URL` 을 `https://api.jaringobe.cloud` 로 **한 번만** 넣으면 끝난다.

터널을 쓸 때는 백엔드 `.env` 를 `FRONTEND_ORIGIN=https://jaringobe.cloud`, `COOKIE_SECURE=true` 로
바꾸고 백엔드를 재기동해야 한다. **로컬 개발로 돌아올 때는 반드시 `http://localhost:3000` / `false`
로 되돌린다** — 안 되돌리면 로컬에서 쿠키가 저장되지 않아 로그인이 되지 않는다.

정식 호스팅처(VPS vs Fly.io·Koyeb + Neon 등)는 **릴리즈 시점에 결정**하기로 미뤄두었다.
이관 절차는 [backend-portable-guide.md](./backend-portable-guide.md). 서버 compose 는 `CYCLE_*`·`EXPO_ACCESS_TOKEN`·`APP_SCHEME` 을 전달하지 않으므로 배포 전 갱신 필요([config-guide.md](./config-guide.md)).

### 소셜 로그인·LLM·시세·푸시 키가 비어 있다
`.env` 의 `KAKAO_*`/`GOOGLE_*`/`ANTHROPIC_API_KEY`/`NAVER_*`/`EXPO_ACCESS_TOKEN` 이 비어 있다.
- 소셜 로그인 불가 → 로그인이 필요한 기능 전체가 막힌다. 각 콘솔에서 재발급 + 콜백 URL 등록 필요
- `ANTHROPIC_API_KEY` 없으면 AI 식단은 mock(냉장고 되먹임 미반영), `NAVER_*` 없으면 시세 없음, `EXPO_ACCESS_TOKEN` 없으면 무인증 발송 시도
- 이 때문에 QA 5항목(실 로그인·실 LLM 되먹임·실 시세·Expo 실발송·스테이징 E2E)이 BLOCKED 로 남아 있다(R-8)
