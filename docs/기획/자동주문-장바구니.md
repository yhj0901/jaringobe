# 자동주문 장바구니 (P0) 기획서

## 개요 | 배경 및 목적

자린고비 3대 축의 마지막 고리 — **식재료 자동 주문** — 을, 실결제·파트너 키 없이 **제품 루프만** 연다. 식단(mealplan)과 가상 냉장고(fridge)는 이미 동작하고, 스토어 연동은 자격증명 없는 플래그(`store_connections`)만 있다. 회원 홈 자동주문 카드는 아직 `LockedFeatureCard feature="order"` 로 "준비 중"이다.

P0 목표는 **동적 감산 장보기 목록 → 연동 표시 기준 시뮬레이션 확정 → 확정 수량을 냉장고에 inbound** 하여 선순환을 닫는 것이다.

```
남은 끼니 재료 − 냉장고 재고 = 필요 품목(needed)
  → (KR·네이버 키 있을 때) 기존 build_cart 로 추정가
  → 사용자가 /orders 에서 명시 탭으로 확정 (status=confirmed, 실결제 아님)
    → 구매(needed) 수량만 fridge inbound source=order
      → 식사 완료 차감 → 다음 preview 가 다시 감산
```

실결제·KR 계정 자동화·US Walmart/Instacart 공식 API·애플 로그인은 **이후 순서**(라이브 KR 시세 → 애플 로그인 → 실결제)로 이관한다. 본 기획은 GATE 1 문서이며 애플리케이션 코드를 포함하지 않는다.

## 범위: In Scope / Out of Scope

### In Scope (파트너 키 없이 구현 가능해야 함)

- **필요 품목 계산**: 최신 식단의 **미완료** 끼니 재료 합 − 냉장고 재고. 정규화 이름(소문자+trim) + 단위 일치로 매칭, 수량 감산. 냉장고에만 있고 식단에 없는 재고는 목록에 올리지 않음 (동적 감산 P0)
- `GET /api/v1/orders/preview` — needed / covered-by-fridge, 선택적 스토어 장바구니 추정 (KR·네이버 키 있으면 기존 `build_cart` 호출. 키 없으면 `matched=false` + note. US 는 네이버 스킵, 필요 품목만 + US 시세 어댑터는 P2 라는 note)
- `POST /api/v1/orders` — 현재 preview 를 **서버가 재계산**해 mock 확정 주문 저장. `status=confirmed`. 실결제·스토어 자격증명 없음. 라인 스냅샷
- `GET /api/v1/orders/latest` — 해당 유저 최신 주문 (없으면 404)
- 확정 시 **구매(needed) 수량만** 냉장고 inbound `source=order`. 이미 냉장고가 충당한 수량은 inbound 하지 않음
- 회원 홈: 잠금 주문 카드를 실제 `AutoOrderCard` 로 교체. 스토어 미연동 → `/settings` CTA. 연동됨 → preview 추천 품목 + "장바구니 보기". 하단 장바구니 탭 → `/orders` 리뷰
- 리뷰 페이지 `/orders`: needed vs covered-by-fridge, 추정 합계(네이버 없으면 0), 확정 버튼 카피 **"연동 표시 기준 시뮬레이션 (실결제 아님)"**. 확정 후 다음 제안일 표시(기본 weekly = 확정 +7일, **표시만**, 스케줄러 잡 없음)
- 확정은 `store_connections.status=connected` 인 스토어가 최소 1개 필요 — 본문 `store` 가 그 연동 스토어여야 함. 미연동 시 422 `STORE_NOT_CONNECTED`. **preview 는 연동 없이 동작**
- i18n ko+en. 주문 행 `frequency=weekly` 기본 저장 (P1 스케줄러용). P0 에 cron 없음
- 신규 도메인 `order` (backend `domains/order`, frontend `features/order`)
- GATE 3: 테이블 `orders` + `order_items`, alembic **0009** (`down_revision=0008`, 0008 = `store_connections_global`)
- 기존 `POST /api/v1/store/cart` 는 **재사용** (Naver 검색 → LLM 선택). api-spec 편입은 **설계 단계** 일 (본 기획서가 api-spec 을 고치지 않음)

### Out of Scope

- 실 체크아웃, 자동 결제, 스토어 자격증명 저장, KR 계정 자동화, US Walmart/Instacart API
- 스케줄러 / 주 2회 주기 UI (`weekly` 기본값 저장만)
- 애플 로그인, 회원 탈퇴, 닉네임 수정
- 식단 생성기·식사완료 냉장고 차감 로직 변경 (이미 출시)
- 게스트 자동주문은 로그인 CTA 샘플 유지 — **게스트 주문 persist 금지**
- `POST /mealplans/{id}/cart`, `POST /mealplans/monthly` 의 제품 UI 편입·삭제 (내부 원스톱으로 유지, 회원 접점은 `/orders/*`)

## 영향 영역

## 관련 도메인

- **order** (중심 — 신규)
- mealplan (최신 식단·미완료 끼니 재료)
- fridge (shortfall 감산 + 확정 inbound `source=order`)
- store (`store_connections` 연동 전제, `POST /store/cart` = `build_cart` 재사용)
- auth (인증 쿠키, 본인 스코프)
- budget (금액 Money 규격만 — 예산 로직 변경 없음)

## BM 연결점

- **구매 전환 중개 수수료**의 제품 퍼널을 실결제 없이 먼저 닫는다. 시뮬레이션 확정 = 전환 의도 신호(향후 수수료 산정 입력)
- 정직한 "실결제 아님" 라벨로 기대 관리 — 가짜 영수증은 신뢰·규제 리스크이므로 금지
- 프리미엄 구독과 무관 (식단 탭 잠금 유지)

## 글로벌 고려

| 항목 | KR | US |
|------|----|----|
| 스토어 세트 | kurly / coupang / ssg / naver (`user.country`) | walmart / instacart |
| 시세 | 네이버 키 있으면 기존 `build_cart`(mall=`kurly`) 추정. 키 없으면 matched=false, total 0 | **네이버 호출 금지**. needed 만 반환. 가짜 USD 가격 금지. note: US 시세 어댑터는 P2 |
| 통화 | KRW (Naver lprice) | 추정가 없음 — `estimatedTotal.amount="0.00"`, currency=USD |
| 카피 | ko/en 동시. 시뮬레이션 고지 필수 | 동일 (실결제 아님 / not a real charge) |
| 주기 표시 | +7일 (weekly) | 동일. 주 1회 대량 배송 전략은 표시만, 스케줄러 없음 |

- `POST /store/cart` 의 `mall` 은 현재 `kurly \| all` 뿐. P0 KR 추정가는 **항상 이 어댑터**를 쓴다. `orders.store` 는 사용자가 연동한 스토어(후속 실결제 대상)이지 네이버 mall 필터가 아니다. 쿠팡 연동 중이어도 추정 카피에 "네이버 쇼핑(컬리) 검색 기준"을 명시한다.

## 비기능 요구사항

- **성능**: `GET /orders/latest` p95 < 300ms. preview 는 네이버 순차조회+LLM 이 붙을 수 있음 — 기존 store 한도(수 초~수십 초) 허용, 프론트 스켈레톤+aria-busy
- **보안**: 아래 보안 요구사항. 실결제 흉내 영수증·가짜 paid 배지 금지
- **접근성**: 확정 버튼 고지 텍스트를 버튼 근처에 일반 텍스트로(색만으로 구분 금지). 리뷰 목록 시맨틱 리스트. 확정 후 라이브 리전으로 다음 제안일 안내
- **비용 방어**: preview 의 `build_cart` 는 기존 store 리미터(3회/분) 재사용. 프론트 연타 방지
- **정직성**: 모든 확정 성공 화면에 "연동 표시 기준 시뮬레이션 (실결제 아님)" / EN 동등 문구 유지. `status` 는 `confirmed` 이지 `paid` 가 아님

## UX 흐름

```
[회원 홈 /]
  ├─ 스토어 0개 연동 → AutoOrderCard 비활성 톤 + CTA "스토어 연동하기" → /settings
  ├─ 1개 이상 연동 → AutoOrderCard 활성
  │     ├─ GET /orders/preview (백그라운드)
  │     │     needed 이름 칩 (최대 N개, 초과는 "+K")
  │     └─ CTA "장바구니 보기" → /orders
  └─ 하단 장바구니 탭 → /orders

[/orders 리뷰] 인증 필수 (미인증 → /login?next=/orders)
  ├─ 식단 없음 → 빈 상태 "먼저 식단을 만들어 주세요" + 홈 CTA
  ├─ needed 없음(전부 냉장고 충당) → covered 목록 + 확정 버튼 비활성 + "살 재료가 없어요"
  └─ needed 있음
        ├─ 섹션 A: 살 재료 (needed) — 매칭 상품명/추정가 또는 "시세 없음"
        ├─ 섹션 B: 냉장고가 충당 (covered) — 수량 fromFridge
        ├─ 추정 합계 (없으면 ₩0 / $0) + 고지 "연동 표시 기준 시뮬레이션 (실결제 아님)"
        └─ [장바구니 확정] 명시 탭
              ├─ 미연동 store → 에러 배너 + 설정 CTA
              ├─ 성공 → 확정 화면: 스냅샷, 다음 제안일(+7일), "냉장고에 담겼어요"
              └─ 실패/429 → 배너+재시도 (클라이언트 라인 재전송 없음)

[게스트 홈] AutoOrderCard 기존 유지 — CTA → /login. 주문 API 호출·persist 없음
```

- 확정은 **명시 탭만**. 홈 진입·preview 조회로 주문을 만들지 않음
- 가짜 결제 완료 영수증(승인번호·카드 마스킹·paid 스탬프) 금지. 배지는 "시뮬레이션 확정"

## 기술 제약사항

- **기존 API 를 모순되게 재정의하지 않음**: 신규는 `/api/v1/orders/*` 만. `/store/cart`(단수) vs `/stores/connections`(복수) 경로는 그대로
- preview/POST 의 감산은 `fridge.compute_shortfall` 재사용. 현재 `_matches` 는 `lower(name)` 이고 **trim 없음** → order 집계와 fridge 매칭 양쪽에 `strip()` 을 맞춰 구현 (fridge 소량 정합, deduct-on-complete 의미 변경 없음)
- 기존 `POST /mealplans/{id}/cart` 는 **전체 끼니**(완료 포함) 집계라 P0 remaining-only 와 다름. 제품 UI 는 `/orders/preview` 를 쓴다. 해당 엔드포인트는 삭제하지 않음
- `build_cart(mall)` 은 `kurly\|all` 만 허용. P0 는 mall=`kurly` 고정. coupang/ssg/naver 전용 검색 어댑터를 만들지 않음
- 네이버 키·LLM 키는 선택. 없어도 preview/확정은 동작해야 함 (matched=false, total 0)
- Apple / Walmart / Instacart 파트너 키 전제 기능 금지
- 프론트: `features/order` 신설. `AutoOrderCard` 는 홈 셸에 유지하고 member CTA/카피만 props 또는 네임스페이스로 확장 — 카드 복제 금지
- `HomeShell` 회원 분기에서 order 잠금 카드만 교체. fridge 활성 카드(`/fridge`) 유지
- 스케줄러(APScheduler/cron/Redis) P0 도입 금지. `next_suggested_at` 은 컬럼+표시
- 구현 브랜치 제안: `feature/auto-order-p0` (설계 5문서 증분 후)
